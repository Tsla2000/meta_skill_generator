# 专用 Skill 设计维度表

阶段四反向设计时逐项判断「这个目标需不需要这一维」，需要才写，不需要就删。十维全写满通常是模板套用的信号。

| 维度 | 写什么 | 哪类目标必写 | 可删的情况 |
|---|---|---|---|
| 角色与目标 | 执行 Agent 的身份、最终目标、成功长什么样 | 全部 | 无 |
| 对象与范围 | 研究或操作的对象界定、包含与排除清单 | 对象有同名歧义、范围易膨胀时 | 对象唯一且边界自明 |
| 前置检查 | 开工前验证工具、材料、权限、登录态、版本 | 依赖特定工具或账号时 | 纯文本处理类 |
| 执行阶段 | 有序阶段，每阶段含动作、判断、产出、失败处理 | 全部多步任务 | 单步任务改为单节步骤 |
| 决策分支 | 证据 A 走哪条路、证据 B 走哪条路、谁拍板 | 路径取决于中间发现时 | 线性流程无分叉 |
| 证据规范 | 结论分级、引用格式、未知清单 | 研究、分析、诊断类 | 纯机械执行类可简化为「留痕」 |
| 工具策略 | 按材料与问题选工具的规则、降级与替代 | 工具多选或工具可能缺失时 | 工具唯一且必用 |
| 避坑清单 | 该领域专有失败模式与禁止动作 | 全部，至少 3 条 | 无，这维是定制感来源 |
| 交付物 | 文件结构、格式、命名、落盘位置 | 产出要被后续使用时 | 一次性口头答复类 |
| 验收标准 | 逐条可复核的通过条件与不通过处理 | 全部 | 无 |

## 阶段颗粒度规则

- 一个阶段只解决一类问题，跨类就拆。
- 阶段名用「动作 + 对象」命名，如「收集公开证据」「还原数据流」，不用「第一步」「深入研究」。
- 阶段之间只用产出物衔接：上一阶段的产出是下一阶段的输入，写明文件名或数据形态。

## 定制感自检

把生成的 Skill 里的目标名替换成另一个不相干的目标，若全文仍然成立超过一半，说明阶段三没做透，回到领域模型重做避坑清单、证据规范与验收三部分。这三部分最难通用化，是每份专用 Skill 的指纹。
