# 生成前质量门（九项）

输出前逐项判定 pass 或 fail，fail 先修。不要在交付时报告自检过程，只交付修好的成品，用户问起才说明。

| # | 检查 | pass 标准 | 常见 fail 形态 |
|---|---|---|---|
| 1 | 真理解 | 能用一句话说出目标的机制层含义，而非字面释义 | 把关键词换成同义词复述了一遍 |
| 2 | 核心能力齐 | 阶段三列的能力在 Skill 阶段里逐项有落点 | 提了关键依赖，正文却没有任何阶段处理它 |
| 3 | 专用工作流 | 换名自检不过半成立（见 skill-anatomy.md） | 章节与上一份生成的 Skill 完全同构 |
| 4 | 前置与失败路径 | 每个外部依赖有检查点，每个阶段有失败处理 | 只写顺利流程，第一步卡住全盘停摆 |
| 5 | 可验证验收 | 每条验收可由第三方按字面复核 | 「高质量」「深入」「全面」出现在验收里 |
| 6 | 无冗余 | 删任一阶段都会损失产出或增加风险 | 为显专业加的背景介绍与礼仪段落 |
| 7 | 可直接开工 | 执行 Agent 五分钟内能说出第一步动作与所需材料 | 第一步是「了解相关背景」类空动作 |
| 8 | 事实与待查分开 | 已确认事实有来源，待查事项进调查清单，假设进假设节 | 把训练记忆写成确定事实 |
| 9 | 边界合规 | 不绕过登录、付费、访问控制，不复制受保护代码与素材，花钱与对外动作需用户批准 | 为达目标默认使用未授权材料 |

## 两轮规则

同一份 Skill 修两轮仍有三项以上 fail，说明目标解剖有根本问题或目标本身不适合 Skill 化。停下，向用户说明卡点并给出替代方案，不要继续打补丁。
