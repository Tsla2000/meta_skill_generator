# 输出模板

## 模式 A：可复制文案（默认）

执行 Agent 拿到就能开工的独立文案。方括号内为填写位，无内容的小节直接删除，不要留空标题。

```markdown
# 专用 Skill：[目标名]

## 目标
[最终要达成的结果，一到三句，必须含可检查的完成标志。]

## 对象与范围
- 对象：[具体对象与版本、形态]
- 包含：[范围]
- 排除：[明确不做的事]

## 假设与边界
- [假设 1 及其不成立时的调整方式]
- 不绕过登录、付费与访问控制。不复制受保护的代码、模板与素材。涉及花钱、对外发布、删除数据，先取得用户批准。

## 开工前检查
- [ ] [工具、材料、权限、登录态，逐项写验证方法与通过标准]

## 执行阶段
### 阶段 1：[动作 + 对象]
- 做：[具体动作，动词开头，写清输入与方法]
- 判：[什么结果算过，什么结果触发分支或重试]
- 产出：[中间成果与落盘位置]
- 失败时：[替代路径或上报方式]

### 阶段 2：[按需增减]

## 证据规范
- 关键结论标注等级：已验证（附证据来源）、推断（附推理链）、未知（进未知清单）。
- [该领域特有的证据要求，如须引原文行号、须附运行截图、须双源互证]

## 禁止与避坑
- [该目标专有错误 1，写清为什么错与正确做法]
- [专有错误 2]
- [专有错误 3]

## 交付物
- [文件或成果清单，含格式与命名]

## 验收标准
- [ ] [可由第三方复核的条件 1]
- [ ] [条件 2]
- 全部通过才可宣称完成。未通过项如实报告，不用「基本完成」代替。
```

## 模式 B：Agent Skills 文件版（用户明确要求时）

目录名用英文 snake_case，与目标对应，如 `launchmotion-rebuild/`。

```text
<skill-slug>/
  SKILL.md          主指令。Muse 本地版无 frontmatter，元数据放 skill.yaml
  skill.yaml        name / title / description / category / include_in_prompt
  references/       长参考、检查清单、领域资料，按需拆分，主文件只留指针
  scripts/          可选。只有确需确定性脚本时才建，脚本必须实测可跑
  examples/         可选。放一份按本 Skill 执行出的样例成果或其结构
```

跨系统移植（Claude Code、Codex 等遵循 agentskills.io 的宿主）时，把 skill.yaml 的 name 与 description 转写为 SKILL.md 顶部的 YAML frontmatter，文件夹名改为与 name 一致的 kebab-case，其余正文不改。详见 `portability.md`。

## 填写纪律

- 模板是上限不是清单：生成的文案小节数应少于或等于模板，目标简单时砍到只剩目标、阶段、避坑、验收四节。
- 每个方括号填完都要过一句自问：执行 Agent 照这句做的第一动作是什么。答不出就重写该句。
